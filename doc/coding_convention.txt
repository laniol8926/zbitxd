This is a short note on the coding conventions followed with the source code of sbitx.

1. For function and variable names, we use all small case with underscore (_) to seperate out
the words (like do_cmd or tx_process).

2. Use static variables that limit the variables' visibility to the particular files and functions
instead of global variables.

3. Practice simpler code over tricky, efficient code. Efficiency should come from eliminating
complex code rather than writing it. Above all, make the code readable and understandable. The
best documentation is cleanly written code.

4. For any new module, develop it as an independent C program with its own main function that can
be used to exercise it and test it out. When adding to the rest of the code, comment out the
main().

5. Use printf to dump debug information and comment it out when adding to the production.
